17 · 编译器与 Ivy 运行时 ​

所属：第七篇 · 精通专题　配套示例：internals（新增 signal 依赖图实验）

学习目标 ​

  • 画出模板从解析、绑定、类型检查到产物生成的完整编译管线
  • 看懂编译产物中等价的 ɵɵelementStart / ɵɵtext / ɵɵlistener 指令序列
  • 说明 Ivy 的组件定义（ComponentDef）与 LView 如何替代旧版 View Engine
  • 解释 signal 的 producer/consumer 关系、computed 的惰性与 memoization
  • 说明 effect 为什么在变更检测阶段运行，而不是写入时立即执行
  • 能从编译与运行时角度解释 @defer、增量水合与 zoneless 的代价

1. 模板不是 HTML：它要被编译两次 ​

Angular 模板既不是运行时字符串，也不是纯 HTML。它先被 Angular 编译器处理，再由 TypeScript 编译成 JS。理解这条链路，很多「为什么不能这样写」就变成了编译期约束，而不是玄学。

  • 解析（parse）：把模板切成元素、属性、文本、控制流块（@if / @for / @defer）。 @angular/compiler 用 TmplAst 系列节点表示。
  • 绑定（bind）：确定每个属性属于哪个指令或组件输入，R3TargetBinder 产出绑定信息。
  • 类型检查（type check）：@angular/compiler-cli 生成模板类型检查代码（TCB），让模板里的 表达式也参与 TypeScript 检查。这是「模板里写错属性名会编译失败」的来源。
  • 生成（emit）：输出 Ivy 指令序列，与组件类一起打包。

关键含义：模板错误在构建期暴露。这也是为什么示例门禁要跑完整 build——只跑类型检查或只跑 测试，都覆盖不到模板编译这一层。

2. 编译产物长什么样 ​

一个最小模板：

html
<p>计数：{{ count }}</p>
<button (click)="inc()">+1</button>

AOT 编译后，等价于下面这类指令调用（实际产物还包含常量池与属性索引，这里只保留结构）：

ts
// 等价形态，不是逐字产物
ɵɵelementStart(0, 'p');
ɵɵtext(1);
ɵɵinterpolate(2, ctx.count);
ɵɵelementEnd();

ɵɵelementStart(3, 'button');
ɵɵlistener('click', () => ctx.inc());
ɵɵtext(4, '+1');
ɵɵelementEnd();

要点：

  1. 指令是命令式的，按顺序创建 DOM，没有虚拟 DOM diff。
  2. 模板只执行一次来建树；后续变化通过绑定更新（ɵɵinterpolate 读到新值后更新文本节点）。
  3. 事件绑定直接挂在原生元素上，不需要框架层的事件代理。
  4. 索引（0、1、2…）指向 LView 槽位，运行时靠它定位数据，而不是靠字符串属性名。

这解释了三个常见现象：为什么 @for 必须 track（需要稳定身份来复用节点）、为什么模板里的 函数调用会在每次检查时执行、为什么动态创建组件要走 ViewContainerRef 而不是拼 HTML 字符串。

3. Ivy 运行时：ComponentDef 与 LView ​

每个组件编译后都有一个定义对象，描述选择器、输入输出、模板函数与依赖：

ts
// 概念形态：ɵɵdefineComponent 生成 ComponentDef
const Def = ɵɵdefineComponent({
  type: Counter,
  selectors: [['app-counter']],
  inputs: { label: 'label' },
  decls: 5,
  template: function (rf, ctx) { /* 指令序列 */ },
});

运行时为每个组件实例创建 LView（逻辑视图）：它保存上下文、子视图、绑定值与 DOM 引用。 更新时框架遍历 LView，执行 template 中的更新分支，而不是重新解析模板。旧版 View Engine 的 View/DebugElement 体系已被这套结构替代。

4. Signal 依赖图：拉取式计算 ​

signal 不是「值 + 订阅者列表」这么简单。运行时维护 producer（signal/computed）与 consumer （computed/effect/模板）的双向关系：读取时登记依赖，写入时标记下游为「脏」。

示例的依赖链是 source → double → quad：

ts
// 文件：src/app/graph-lab.ts
protected readonly double = computed(() => {
  this.doubleRuns++;
  return this.source() * 2;
});

protected readonly quad = computed(() => {
  this.quadRuns++;
  return this.double() * 2;
});

行为规则：

  • 惰性：computed 不会因为上游写入就立刻计算，只有被读取时才求值。
  • 缓存：依赖版本没变时，重复读取直接返回缓存值，doubleRuns 不会增加。
  • 传播：写入 source 只把下游标记为脏，真正重算发生在下一次读取或渲染。
  • effect 不同：effect 是 consumer，但它的调度要经过变更检测调度器，在渲染阶段批量执行。

在示例中反复点击「source +1」，可以观察两件事：source 每变一次，double 与 quad 各只重算 一次；effect 的记录按批次出现，而不是每次写入立刻插入一条。把模板里的 double() 与 quad() 删掉，再观察计算次数，你会看到「没人读就不算」的惰性。

5. 调度：为什么 effect 不立即执行 ​

效果（effect）需要读 DOM、写状态或调用外部系统，如果同步执行，很容易在渲染中途读到不一致的 DOM。Angular 把 effect 排进变更检测周期，由调度器统一刷新；zoneless 下这个调度器不再依赖 Zone.js 的宏任务补丁，而由 signal 写入、事件、markForCheck 等显式通知。

这与第 12 章的 OnPush 实验是同一套机制的两个视角：那边看「组件要不要检查」，这里看「检查时 依赖图怎么求值」。untracked() 则用于在 consumer 内读取 signal 但不建立依赖，通常出现在需要 「只读一次当前值」的副作用里。

6. 编译期能力：@defer 与增量水合 ​

@defer 不是运行时判断，而是编译器识别出的延迟块：它会生成独立的依赖图与指令标记，打包器 据此拆分 chunk，运行时按触发条件加载并激活。增量水合同理——服务端输出的延迟块带有标记，浏览器 按需水合。

这解释了两个实践结论：

  1. 「写了 @defer 但没拆包」通常是静态引用导致的，编译器无法把块外也在用的依赖移走。
  2. 「水合后交互延迟」要看块是否被独立水合，而不是只看 JS 是否下载完成。

7.1 建议先改这里 ​

  1. 连续点击「source +1」十次，观察两个计算次数的增长。验收：每次点击后 double 与 quad 各 增加 1，而不是指数增长。
  2. 注释掉模板里的 {{ quad() }}，只保留 effect。验收：quadRuns 仍随写入增加，因为 effect 仍 在读它；再注释 effect，quadRuns 停止增长。
  3. 把 double 的返回值改成 this.source() * 3。验收：quad 结果从 4 倍变为 6 倍，说明依赖链 自动传播，不需要手动订阅。
  4. 在 effect 中把 this.quad() 换成 untracked(() => this.quad())。验收：effect 不再随 source 变化重新运行，日志停止更新，而模板仍正常刷新。
  5. 回到「变更检测实验」卡片，点击「异步 +1（不刷新）」，再点 detectChanges()。验收：普通字段 的变化只有在手动检查后才出现，而 signal 的变化立即刷新。

9. 练习 ​

  1. 给 graph-lab 增加第三个 computed（source + 1），观察它是否与 double 共享上游依赖。 验收：写入一次 source，两个分支各重算一次，互不影响。
  2. 把一个 effect 改成 afterRenderEffect，比较日志出现时机。验收：你能说明它在渲染前后哪个 阶段执行，以及为什么不适合读业务状态。
  3. 在模板中把 @for 的 track $index 改为 track line，并让日志出现重复字符串。验收：你能 观察到节点复用与状态错位的差异。
  4. 用 ng build 产物搜索模板指令名（如 ɵɵelementStart）。验收：能在压缩前的产物中找到对应 指令，理解编译产物与源码的对应关系。
  5. 给 @defer 块增加一个只在块内使用的子组件，构建后检查 chunk。验收：子组件进入独立 chunk， 而不是主包。

10. 自测 ​

1. 为什么 Angular 模板不需要虚拟 DOM？

编译器把模板变成有序的 DOM 创建指令，并给每个动态绑定分配槽位。首次渲染建树，后续更新直接改 对应节点或绑定，不需要先构造一棵虚拟树再比对。代价是更新逻辑由编译器生成，而不是运行时通用 diff。

2. computed 的「惰性」和「缓存」分别指什么？

惰性指上游变化不会立即触发计算，只有被读取时才求值；缓存指依赖版本没变时重复读取返回上一次 结果，不重复执行函数。两者共同保证「读多少算多少、没变就不算」。

3. effect 为什么不能像普通回调一样同步执行？

effect 可能读写 DOM 或触发新的状态变化。同步执行会插入渲染中间态，导致读到不一致的 DOM，也可 能引发重入。交给调度器在变更检测阶段批量执行，能保证顺序与一致性。

4. 模板类型检查（TCB）解决了什么问题？

它把模板表达式与指令输入放进 TypeScript 的类型系统，让属性名、参数类型、事件类型错误在构建期 暴露。没有它，模板错误只能等运行时才发现。

本章小结 ​

  • 模板先经解析、绑定、类型检查与指令生成，才变成可执行代码。
  • Ivy 用指令序列建树、用 LView 保存状态，更新不依赖虚拟 DOM diff。
  • signal 依赖图是拉取式的：写入标记脏，读取才求值，computed 带缓存。
  • effect 由调度器在变更检测阶段执行，untracked 可切断意外依赖。
  • @defer 与增量水合是编译期识别的块，拆包与激活都依赖引用图。
