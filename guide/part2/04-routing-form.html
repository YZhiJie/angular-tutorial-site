04 · 路由与响应式表单 ​

所属：第二篇 · 基础　配套示例：routing-form

学习目标 ​

  • 能用 provideRouter(routes) 注册路由，并正确放置通配路由。
  • 能启用 withComponentInputBinding()，把 :id 参数绑定到组件 input。
  • 能用 FormBuilder.nonNullable.group 构建带类型的响应式表单。
  • 能编写跨字段校验器，并在模板中按 touched 与 hasError 展示错误。
  • 能在提交时统一标记字段，避免只提示第一个错误。

1. 路由、参数与表单的三条主线 ​

1.1 路由表：路径、组件与兜底 ​

ts
// 文件：src/app/app.routes.ts
import { Routes } from '@angular/router';
import { Home } from './home';
import { Signup } from './signup';
import { UserDetail } from './user-detail';
export const routes: Routes = [
  { path: '', component: Home },
  { path: 'signup', component: Signup },
  { path: 'user/:id', component: UserDetail },
  { path: '**', redirectTo: '' },
];

空路径匹配首页，user/:id 的 :id 是路径参数，** 匹配所有未命中的地址并重定向。通配路由必须放在最后，否则会抢先吞掉后面的具体路由。示例采用直接引用组件的方式；需要按需加载时，可改成 loadComponent，路由表结构不变。

1.2 参数绑定：少写一段订阅代码 ​

应用启动时用 provideRouter(routes, withComponentInputBinding()) 注册路由。第二个参数启用输入绑定，Angular 会按名称把路径参数写入组件的同名 signal 输入。

ts
// 文件：src/app/user-detail.ts
import { Component, input } from '@angular/core';

@Component({
  selector: 'app-user-detail',
  template: '<p>当前用户 ID：<strong>{{ id() }}</strong></p>',
})
export class UserDetail {
  // 启用 withComponentInputBinding 后，路由参数会直接绑定到 input
  readonly id = input.required<string>();
}

withComponentInputBinding() 让 Angular 按名称把 :id 写入同名的 signal 输入。组件不需要注入 ActivatedRoute 再订阅 params，也不会忘记取消订阅。路径参数按字符串传入，/user/42 得到的是 '42' 而不是数字 42。

1.3 响应式表单：类型、校验与提交 ​

ts
// 文件：src/app/signup.ts（节选：省略 @Component 装饰器）
import { Component, inject, signal } from '@angular/core';
import { FormBuilder, Validators } from '@angular/forms';
import { passwordMatch } from './password-match';

export class Signup {
  private readonly fb = inject(FormBuilder);
  protected readonly submitted = signal(false);
  protected readonly form = this.fb.nonNullable.group(
    {
      email: ['', [Validators.required, Validators.email]],
      password: ['', [Validators.required, Validators.minLength(8)]],
      confirm: ['', [Validators.required]],
    },
    { validators: passwordMatch() },
  );
  protected submit(): void {
    this.submitted.set(true);
    if (this.form.invalid) {
      // 让所有字段立即显示错误，而不是只提示第一个
      this.form.markAllAsTouched();
      return;
    }
    console.log('提交数据', this.form.getRawValue());
  }
}

nonNullable.group 让每个控件的值类型都是 string 而非 string | null。组件在 imports 中声明 ReactiveFormsModule，模板才能使用 formGroup 等指令。字段级校验器放在数组里，跨字段校验器放在 group 的 validators 选项里，作用于整个表单。submitted 用 signal 记录是否点过提交，模板据此决定是否显示“仍有错误”的汇总提示。

ts
// 文件：src/app/password-match.ts（节选）
import { AbstractControl, ValidationErrors, ValidatorFn } from '@angular/forms';

// 跨字段校验：返回 null 表示通过，返回对象表示具体错误
export function passwordMatch(): ValidatorFn {
  return (group: AbstractControl): ValidationErrors | null => {
    const password = group.get('password')?.value;
    const confirm = group.get('confirm')?.value;
    if (!password || !confirm) return null;
    return password === confirm ? null : { passwordMismatch: true };
  };
}

校验器返回 null 表示通过，返回带键的对象表示失败，键名就是后续 hasError 查询的名称。两个字段任一为空时直接放行，把“必填”交给各自的 required，避免空表单同时显示多重错误。

2. 动手步骤 ​

bash
cd examples/routing-form
npm start

打开 http://localhost:4200，依次访问：

  1. / 显示首页；点击“注册”进入 /signup，点击“用户 42”进入详情页。
  2. 直接刷新 /user/42，页面仍显示 42，说明参数绑定不依赖导航时的内存状态。
  3. 打开 /unknown，通配路由把地址重定向回首页，地址栏随之变化。

关键文件职责：

  • app.routes.ts：路径与组件映射，包含通配兜底。
  • app.config.ts：注册 provideRouter 并启用输入绑定。
  • signup.ts / password-match.ts / signup.html：表单模型、跨字段校验与错误展示。

4. 代码拆解 ​

4.1 表单模板：按 touched 展示错误 ​

html
<!-- 文件：src/app/signup.html（节选） -->
<form [formGroup]="form" (ngSubmit)="submit()" novalidate>
  <label for="email">邮箱</label>
  <input id="email" type="email" formControlName="email" autocomplete="email"
    [attr.aria-invalid]="form.controls.email.touched && form.controls.email.invalid" />
  @if (form.controls.email.touched && form.controls.email.invalid) {
    <p class="error" role="alert">
      @if (form.controls.email.hasError('required')) { 邮箱不能为空。 }
      @if (form.controls.email.hasError('email')) { 请输入合法的邮箱地址。 }
    </p>
  }

  <button type="submit">提交注册</button>
</form>

[formGroup] 把表单模型接到原生 form，formControlName 把输入框与具体控件关联。错误只在 touched 后显示，避免用户还没输入就满屏红字。跨字段错误的查询对象是 form 而不是单个控件，因为校验器挂在 group 上；模板里对应写 form.hasError('passwordMismatch')。role="alert" 与 aria-invalid 让错误可被辅助技术感知。

4.2 导航与出口 ​

html
<!-- 文件：src/app/app.html -->
<main class="page">
  <nav>
    <a routerLink="/">首页</a>
    <a routerLink="/signup">注册</a>
    <a routerLink="/user/42">用户 42</a>
  </nav>
  <router-outlet />
</main>

RouterLink 生成的是站内导航，不会触发整页刷新；<router-outlet /> 是路由组件的渲染位置。App 组件在 imports 中声明 RouterLink 与 RouterOutlet 后才能使用这两个指令。导航栏属于布局层，因此放在出口之外，切页时保持不变。

5. 常见坑 ​

现象原因处理
点击导航整页刷新使用原生 href 而非 routerLink改成 routerLink，并导入 RouterLink
通配路由抢占了其他页面path: '**' 写在具体路由之前把通配项移到数组末尾
详情页拿不到参数未启用 withComponentInputBinding，或 input 名称与参数不一致启用绑定，并保持 input 名称与 :id 同名
提交后没有任何错误提示只检查了 invalid，没有标记 touched提交时调用 markAllAsTouched()
密码不一致却不报错校验器挂在字段上，而不是 group 上把 passwordMatch() 放进 group 的 validators

6. 练习 ​

  1. 限制邮箱长度：给 email 增加 Validators.maxLength(64)，并在模板显示对应错误。验收标准：输入 65 个字符后出现“邮箱过长”提示，表单变为无效。
  2. 新增昵称字段：添加可选 nickname，不设必填。验收标准：不填也能提交，getRawValue() 输出包含空的昵称字段。
  3. 改参数与链接：把路由改为 user/:id 保持不变，在首页增加 /user/7 链接。验收标准：点击后详情显示 7，刷新仍显示 7。
  4. 有效才启用提交：给按钮加 [disabled]="form.invalid"。验收标准：空表单按钮禁用；填写合法邮箱、8 位以上且一致的密码后按钮可用。

7. 自测 ​

1. withComponentInputBinding 解决了什么问题？

它把路由参数、query 参数等按名称绑定到组件的 signal 输入，组件无需注入 ActivatedRoute 再订阅参数流。参数变化时输入自动更新，也省去了手动取消订阅的负担。

2. 为什么跨字段校验器要挂在 group 上？

passwordMatch 需要同时读取密码与确认密码，字段级校验器只能看到当前控件的值。挂到 group 上后，校验器能通过 group.get() 读取多个控件，并把 passwordMismatch 记录在表单层级，供模板用 form.hasError 查询。

3. nonNullable 的作用是什么？

默认情况下，控件的值类型包含 null，读取时要做空值判断。nonNullable.group 让控件值类型收敛为 string，模板与提交逻辑都更直接。代价是需要为每个控件提供合理的初始值。

本章小结 ​

  • 路由表用 provideRouter 注册，通配项放最后；RouterLink 与 RouterOutlet 分别负责导航和渲染位置。
  • withComponentInputBinding() 把路径参数按名称绑定到 input，参数类型是字符串。
  • 响应式表单用 FormBuilder.nonNullable.group 构建，字段校验与跨字段校验分层放置。
  • 错误展示依赖 touched 与 hasError，提交时用 markAllAsTouched() 让所有问题同时可见。
