07 · 懒加载与构建优化 ​

所属：第四篇 · 工程化　配套示例：build-lab

学习目标 ​

  • 能用 loadComponent 把路由页面拆成独立 chunk，并解释首屏为什么不再包含它
  • 能用 @defer 的触发条件、@placeholder 与 @loading 控制延迟加载的体验
  • 能判断哪些依赖会随 @defer 一起分包，哪些会把主包重新撑大
  • 能说明 OnPush 与 signal 在 zoneless 下如何减少不必要的检查
  • 能读懂 angular.json 的 initial / anyComponentStyle 预算并据此做取舍
  • 能用 --stats-json 产物核对首屏与懒加载 chunk，而不是凭直觉判断

1. 首屏体积由引用关系决定 ​

打包器不会因为一个组件「写在另一个文件里」就自动拆包，它看的是静态引用图：只要模块在启动路径上 被 import，就会进入首屏包。示例的首页只保留介绍与统计卡片，报表页通过动态 import() 声明为 路由级懒加载，因此首次访问时不会下载报表代码。

ts
// 文件：src/app/app.routes.ts
export const routes: Routes = [
  { path: '', loadComponent: () => import('./home').then((m) => m.Home) },
  { path: 'reports', loadComponent: () => import('./reports').then((m) => m.Reports) },
  { path: '**', redirectTo: '' },
];

loadComponent 接收一个返回 Promise 的函数，路由匹配成功后才执行 import()。这里的 import() 是打包器的分包边界：两个页面各自形成一个延迟 chunk，主包只保留路由配置与根组件。** 通配路由 把未知地址重定向回首页，避免用户看到空白页。

bash
npm run build

产物位于 dist/build-lab/browser/，首屏与报表页分属不同 chunk。构建结果是判断有没有拆成功的 唯一依据。不要凭感觉认为「已经懒加载」——打开产物目录，确认报表组件没有出现在首屏入口 chunk 的引用链里。

1.1 用 stats.json 核对分包 ​

示例的 package.json 提供了 stats 脚本，把构建统计写到 dist/build-lab/browser-stats.json：

bash
npm run stats

Angular 22.2.3 在示例源码上的实际构建结果如下（数字会随代码变化，方法不变）：

styles-*.css全局样式313 B313 B

2. 三种手段各管什么 ​

路由级懒加载：按页面拆。 适合访问频率低、体积大的独立页面，例如报表、设置、帮助中心。它解决 「首次访问不下载」，但用户一旦进入该路由，仍会一次性下载整页代码。

@defer：按区块拆。 首页的统计卡片用 @defer (on idle) 包裹，浏览器空闲时才加载。Angular 会把只在这个块里使用的依赖（这里是 Stats 组件）移入延迟 chunk；如果同一个组件还在块外被静态 引用，它就会留在主包，拆分包失效。

html
<!-- 文件：src/app/home.html -->
@defer (on idle) {
  <app-stats />
} @placeholder {
  <p class="ph">统计卡片将在浏览器空闲时加载。</p>
} @loading (minimum 300ms) {
  <p class="ph">统计卡片加载中...</p>
}

@placeholder 在延迟块尚未开始时显示，@loading 在下载与渲染期间显示。minimum 300ms 是展示 下限，用来避免加载太快导致文案一闪而过；它不是「等待 300ms 才开始加载」。on idle 依赖浏览器 空闲回调，在性能较好的机器上可能几乎立即触发，所以 placeholder 不一定肉眼可见。

OnPush 与 signal：按组件减少检查。 Stats 和 Reports 都声明了 changeDetection: ChangeDetectionStrategy.OnPush。在 zoneless 下，组件只在输入引用变化、模板事件 触发、或它读取的 signal 变化时被检查。Stats 的 total 与 peak 是 computed，数据源是一个 私有 signal；只要 signal 不变，统计卡片就不会被反复计算。

ts
// 文件：src/app/stats.ts
export class Stats {
  private readonly samples = signal([12, 18, 9, 24, 16]);
  protected readonly total = computed(() => this.samples().reduce((sum, value) => sum + value, 0));
  protected readonly peak = computed(() => Math.max(...this.samples()));
}

构建预算：把体积变成可失败的指标。 示例的 production 配置给首屏包和单组件样式都设了阈值。 超出 maximumWarning 会警告，超出 maximumError 会让构建失败，这样体积回退不会悄悄进入主分支。

以下是 angular.json 中 production 配置的节选：

json
"production": {
  "budgets": [
    { "type": "initial", "maximumWarning": "500kB", "maximumError": "1MB" },
    { "type": "anyComponentStyle", "maximumWarning": "4kB", "maximumError": "8kB" }
  ],
  "outputHashing": "all"
}

outputHashing: "all" 给产物文件名加内容哈希，配合长期缓存：内容不变则文件名不变，内容变化则 浏览器必然拉取新文件。Angular 22 的 @angular/build 在 production 下默认开启压缩与 tree-shaking，真正需要你决策的是「什么该进首屏」和「预算设在哪里」。

3.1 建议先改这里 ​

  1. 把首页的 @defer (on idle) 改成 @defer (on interaction)。验收：首屏只显示 placeholder， 点击页面任意位置后才出现统计卡片。
  2. 把 @loading (minimum 300ms) 改成 minimum 1500ms，并在浏览器开发者工具里把网络限速为 Slow 3G。验收：加载文案至少停留 1.5 秒，不会瞬间消失。
  3. 修改 placeholder 的文案并加上一个按钮。验收：按钮属于占位内容，延迟块开始后整块被统计卡片 替换，按钮不会残留。
  4. 从首页点击「打开报表页」，再返回首页。验收：地址变为 /reports，报表表格渲染三行数据， 返回后首页仍可正常交互。
  5. 运行 npm run stats，打开 dist/build-lab/browser-stats.json。验收：能找到 home、reports 与 stats 三个独立 chunk，且 main 的体积没有把它们吞进去。

4. 代码拆解 ​

路由配置只负责「什么时候加载哪个组件」，不负责组件内部实现。通配路由放在最后，保证更具体的 reports 先匹配。

ts
// 文件：src/app/app.routes.ts
{ path: '', loadComponent: () => import('./home').then((m) => m.Home) },
{ path: 'reports', loadComponent: () => import('./reports').then((m) => m.Reports) },
{ path: '**', redirectTo: '' },

首页自身也保持轻量：只引入 RouterLink 和延迟块中使用的 Stats，并声明 OnPush。模板中的 @defer 把统计卡片及其依赖从首屏渲染路径中分离出去。

ts
// 文件：src/app/home.ts
@Component({
  selector: 'app-home',
  imports: [RouterLink, Stats],
  changeDetection: ChangeDetectionStrategy.OnPush,
  templateUrl: './home.html',
  styleUrl: './home.css',
})
export class Home {}

报表页用 signal 保存行数据，模板用 @for 并 track row.id。即使数据后续通过 update 替换， OnPush 也能依据 signal 通知精确刷新，而不是整棵树重新检查。

ts
// 文件：src/app/reports.ts
protected readonly rows = signal([
  { id: 1, name: '渠道 A', amount: 1280 },
  { id: 2, name: '渠道 B', amount: 960 },
  { id: 3, name: '渠道 C', amount: 2140 },
]);

根组件只负责导航与路由出口。RouterOutlet 是懒加载页面真正被挂载的位置，导航链接本身不会 触发报表代码的下载。

ts
// 文件：src/app/app.ts
@Component({
  selector: 'app-root',
  imports: [RouterLink, RouterOutlet],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}

6. 练习 ​

  1. 新增一个 about 页面，用 loadComponent 注册 /about，并从首页链接过去。验收：路由可访问， 构建产物中该页面不在首屏入口 chunk 内。
  2. 把统计卡片的触发条件改成 on viewport，并让首页内容足够长，使卡片初始在视口外。验收：滚动到 卡片附近时才开始加载。
  3. 给 Stats 增加一个「追加样本」按钮：按钮通过 samples.update 追加随机数。验收：总量与峰值 立即更新，且无需手动调用变更检测。
  4. 临时把 initial 的 maximumWarning 调到 100kB，运行构建。验收：构建给出预算警告，你能 指出至少一个可延迟加载的模块，并说明恢复预算的理由。
  5. 给 reports 页加一个按金额降序排序的 computed。验收：表格顺序变化，类型检查通过，且没有 引入新的首屏依赖。

7. 自测 ​

1. 路由懒加载和组件静态 import 的本质区别是什么？

静态 import 会把模块放进当前 chunk，启动时就要下载并解析；loadComponent 中的动态 import() 把模块放到独立 chunk，只有路由匹配时才请求。前者影响首屏体积，后者把成本推迟到真正访问时。

2. 为什么 `@defer` 里的组件有时没有被拆出去？

只有当依赖「仅」在该延迟块中使用时，Angular 才能把它移入延迟 chunk。如果同一组件在块外也被 静态引用，打包器必须把它保留在主包，否则块外代码无法启动。拆包前要检查引用图，而不是只看模板。

3. OnPush 能减小包体积吗？

不能。OnPush 影响的是运行时变更检测的范围与频率，不改变打包结果。减小体积靠懒加载、延迟加载 与删除无用依赖；OnPush 与 signal 配合，减少的是不必要的组件检查与计算。

4. initial 与 anyComponentStyle 两种预算分别约束什么？

initial 约束首屏入口及其同步依赖的总体积，用来防止主包膨胀；anyComponentStyle 约束单个组件 样式文件的体积，用来防止某个组件把大量样式塞进产物。两者都可以设置 warning 与 error 两级阈值。

本章小结 ​

  • 静态引用决定首屏包，路由懒加载与 @defer 都要以构建产物验证是否真正拆开。
  • @defer 的触发条件决定加载时机，placeholder 与 loading 决定等待期间的体验。
  • OnPush 与 signal 优化的是运行时检查，不是包体积。
  • 构建预算是可执行的体积约束，超出阈值应让构建失败而不是口头约定。
  • --stats-json 把「是否拆开」变成可核对的产物清单，首屏合计与懒加载 chunk 一目了然。
