01 · 环境搭建与第一个组件 ​

所属：第一篇 · 入门　配套示例：hello-binding

学习目标 ​

  • 能用 Angular CLI 22 创建 standalone 工程，并说清 src/ 下关键文件的职责。
  • 能解释 bootstrapApplication(App, appConfig) 如何把根组件挂到宿主页面。
  • 会用 signal 保存组件状态，并通过 set 与 update 修改。
  • 能在模板里正确使用插值、事件绑定、class 绑定和内置管道。
  • 能用 @if / @else 写出条件分支，并解释视图为什么自动刷新。

1. 没有 NgModule 的 Angular 应用 ​

Angular 22 的新工程默认是 standalone 形态：根组件通过 bootstrapApplication 直接启动，不再需要 AppModule。一个最小工程的结构如下：

bash
hello-binding/
├── src/
│   ├── app/
│   │   ├── app.ts          # 根组件：状态与行为
│   │   ├── app.html        # 根组件模板
│   │   ├── app.css         # 组件私有样式
│   │   └── app.config.ts   # 应用级 providers
│   ├── main.ts             # 浏览器启动入口
│   ├── index.html          # 宿主页面，内含 <app-root>
│   └── styles.css          # 全局样式
├── angular.json            # CLI 构建与开发服务器配置
└── package.json

入口只做一件事：把根组件和配置交给 Angular。

ts
// 文件：src/main.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig)
  .catch((err) => console.error(err));

appConfig 是应用级的依赖注入容器配置。当前示例只注册了浏览器全局错误监听，后续章节的路由、HTTP 客户端都会加进这个 providers 数组。

ts
// 文件：src/app/app.config.ts
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners()],
};

Angular 22 默认采用 zoneless 变更检测。视图刷新不再依赖 Zone.js 对异步 API 的猴子补丁，而是由 signal 写入、模板事件等显式信号触发调度。这意味着：状态必须通过 Angular 认识的方式修改，组件才能可靠地更新。

2. 创建并启动工程 ​

先确认 Node 版本，Angular 22 要求 22.13 以上：

bash
node -v
npm -v

用固定版本的 CLI 创建工程，关闭 SSR 并选择 CSS：

bash
npx @angular/cli@22.2.3 new hello-binding --style=css --ssr=false
cd hello-binding
npm start

npm start 对应 package.json 里的 ng serve。终端出现编译成功后，打开 http://localhost:4200 就能看到默认欢迎页。

需要重点认识的四个文件：

  • src/main.ts：启动入口，决定用哪个根组件、哪个配置启动。
  • src/app/app.ts：根组件类，本例中定义计数、框架名和当前时间三个 signal。
  • src/app/app.html：模板，所有绑定表达式都在这里求值。
  • src/app/app.config.ts：应用级 providers，是后续接入路由与 HTTP 的位置。

把本节示例的四个 app.* 文件内容替换进去，保存后开发服务器会自动热更新。

3. 可运行示例 ​

双绑定计数器

插值、事件绑定、class 绑定与内置管道的最小闭环。

示例会在滚动到此处时加载，首次启动需要等待依赖安装。

页面左侧是计数器，右侧展示框架名的大写结果与渲染时间。所有交互都在浏览器内完成，不需要额外安装。

3.1 建议先改这里 ​

  1. 把模板里的 increase(1) 改成 increase(10)，再点击“+1”。按钮文案没变，但每次实际增加 10，说明事件绑定调用的是方法参数而不是按钮文字。
  2. 把 count() >= 10 改成 count() >= 5，观察提示文案与 output 的高亮样式是否在计数到 5 时切换。
  3. 把 framework 的初始值改成 'Angular Signals'，大写管道会输出 ANGULAR SIGNALS，验证管道在每次 signal 变化后重新执行。

4. 代码拆解 ​

4.1 状态全部用 signal 表达 ​

ts
// 文件：src/app/app.ts
import { Component, signal } from '@angular/core';
import { DatePipe, UpperCasePipe } from '@angular/common';

@Component({
  selector: 'app-root',
  imports: [DatePipe, UpperCasePipe],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {
  // signal 是响应式原语：读取用 count()，写入用 set / update
  protected readonly count = signal(0);
  protected readonly framework = signal('Angular');
  protected readonly today = signal(new Date());

  protected increase(step: number): void {
    // update 基于旧值计算，避免读到过期的快照
    this.count.update((value) => value + step);
  }

  protected reset(): void {
    this.count.set(0);
  }
}

三个要点：

  • signal(0) 返回一个带 () 调用签名的容器。模板与类里都必须 count() 才能读到值，写成 count 拿到的是函数本身。
  • set 用于直接替换，update 用于基于旧值计算。并发或连续点击时，update 能保证每次都在最新值上累加。
  • imports 数组声明了模板要用的独立指令与管道。UpperCasePipe 和 DatePipe 不导入，模板编译就会失败。

4.2 模板里的四类绑定 ​

html
<!-- 文件：src/app/app.html -->
<main class="card">
  <h1>你好，{{ framework() }}！</h1>
  <p class="muted">这是第一个可以真实运行的 Angular 组件。</p>

  <section class="counter">
    <button type="button" (click)="increase(1)">+1</button>
    <button type="button" (click)="increase(5)">+5</button>
    <button type="button" class="ghost" (click)="reset()">归零</button>
    <output [class.hot]="count() >= 10">当前计数：{{ count() }}</output>
  </section>
  @if (count() >= 10) {
    <p class="hint">已经达到 10 次，试着把模板里的步长 1 改成 10。</p>
  } @else {
    <p class="hint">点击按钮，signal 更新后视图会自动刷新。</p>
  }

  <dl class="meta">
    <dt>框架</dt>
    <dd>{{ framework() | uppercase }}</dd>
    <dt>渲染时间</dt>
    <dd>{{ today() | date: 'yyyy-MM-dd HH:mm:ss' }}</dd>
  </dl>
</main>
  • 插值：双大括号内是组件上下文的表达式，signal 必须调用。
  • 事件绑定：圆括号包住 DOM 事件名，右侧是组件方法调用；$event 可拿到原生事件对象。
  • class 绑定：[class.hot] 在表达式为真时追加 hot 类，为假时移除，不会覆盖其他 class。
  • 管道：竖线把左侧值交给管道处理，date 管道用冒号传参数，格式串写在引号里。
  • 控制流：@if 与 @else 是编译器语法，不是普通 DOM 属性，不需要导入任何指令。

4.3 启动链路 ​

index.html 里只有 <app-root></app-root>。main.ts 调用 bootstrapApplication 后，Angular 找到 selector: 'app-root' 的组件，创建实例、应用 appConfig 的 providers，并完成首次渲染。之后每次点击按钮，update 写入 signal，模板中读取过该 signal 的绑定被标记为脏，调度器在微任务中刷新对应 DOM 节点。

5. 常见坑 ​

现象原因处理
模板显示的是函数体而不是数字写成 count 而不是 count()signal 必须调用读取，模板与方法内都一样
赋值时报 “Cannot assign to read only property”把 signal 当普通字段直接赋值用 set 或 update 写入
大写或日期管道报未知管道组件 imports 里漏了 UpperCasePipe / DatePipe在 standalone 组件的 imports 中补上
@if 报语法不完整混用了 *ngIf 写法，或条件外漏了括号使用 @if (条件) { 内容 } @else { 其他内容 }，不要与旧结构指令混写

6. 练习 ​

  1. 改初始值与阈值：把初始计数改为 7，按钮改为 +1 / +5，达到 12 时显示“达标”。验收标准：首屏显示 7；点两次 +5 后显示 17 且提示出现；归零后提示消失。
  2. 增加减一按钮：新增 decrease 方法，计数不小于 0。验收标准：计数为 0 时点击减一仍为 0；从 5 减到 0 的过程中提示按阈值正确切换。
  3. 显示双倍值：在计数旁显示 count() * 2 的结果。验收标准：计数变化时双倍值同步变化，0 时显示 0，不允许出现 NaN。

7. 自测 ​

1. 为什么模板里写 count 会显示函数源码？

count 是 signal() 返回的函数对象，本身不是数值。必须写成 count() 调用它，Angular 才能拿到当前值，同时在求值过程中建立依赖关系。写成 count 相当于把函数转成字符串展示。

2. set 与 update 应该怎么选？

需要用一个全新值覆盖时用 set，例如归零。需要基于当前值推导下一个值时用 update，例如累加步长。update 的回调参数就是最新值，可以避免先读后写之间被其他更新插入而导致丢失。

3. bootstrapApplication 的第二个参数是什么？

它是 ApplicationConfig，核心字段是 providers。Angular 会以它为根注入器配置，provideBrowserGlobalErrorListeners()、后续的 provideRouter 与 provideHttpClient 都在这里注册。省略该参数也能启动，但得不到这些应用级能力。

本章小结 ​

  • Angular 22 工程默认 standalone，main.ts 通过 bootstrapApplication 启动根组件，appConfig.providers 承载应用级能力。
  • signal 是组件状态的首选容器：读取靠调用，写入靠 set / update。
  • 模板绑定分为插值、事件、属性/class 与管道四类，组件用到的管道必须写进 imports。
  • 内置控制流 @if / @else 由编译器处理，不需要额外导入指令。
  • 模板读取 signal 即建立依赖，写入后视图在调度器中刷新；下一章会在这个基础上加入列表渲染、@switch、组件输入输出与内容投影：02 模板语法与组件通信。
