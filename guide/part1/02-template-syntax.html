02 · 模板语法与组件通信 ​

所属：第一篇 · 入门　配套示例：template-syntax

学习目标 ​

  • 能用 @for 渲染列表，写出稳定的 track 表达式，并用 @empty 处理空状态。
  • 能用 @switch / @case / @default 表达多分支，知道它与 @if 的取舍。
  • 能用 input() 与 input.required() 声明输入，并在模板中按 signal 读取。
  • 能用 output() 向父组件发送事件，并在父模板中用 $event 接收载荷。
  • 能用 <ng-content /> 做内容投影，把父组件提供的片段渲染到子组件内部。

1. 模板语法与组件通信的三个支点 ​

1.1 用 @for 渲染列表，用 @empty 兜底 ​

Angular 17 起提供内置控制流，模板不再需要导入 NgFor / NgIf。列表写法如下：

html
@for (member of visibleMembers(); track member.id) {
  <app-user-card [name]="member.name" />
} @empty {
  <p class="empty">没有符合条件的成员。</p>
}

@for 的头部包含循环变量、被遍历的表达式与 track 表达式。track member.id 告诉渲染器每一行的身份，列表重排时才能复用正确的 DOM 节点；写成 track $index，删除中间一项会让后续行的状态错位。

@empty 只在集合长度为 0 时渲染。循环体内还可使用 $index、$first、$last、$even、$odd 等上下文变量。

1.2 用 @switch 表达等值分支 ​

html
@switch (visibleMembers().length) {
  @case (0) {
    <p class="summary">列表为空。</p>
  }
  @case (1) {
    <p class="summary">只有一位成员。</p>
  }
  @default {
    <p class="summary">共 {{ visibleMembers().length }} 位成员。</p>
  }
}

@switch 用严格相等比较表达式与 @case 的值，适合枚举型分支；范围判断、布尔组合仍应使用 @if / @else if / @else。两种语法都由编译器转换，不需要在 imports 中声明。

1.3 input() 与 output()：signal 化的组件契约 ​

子组件的输入用 input() 声明，它返回只读 signal，模板里必须调用读取。示例中的 UserCard 用 input.required<string>() 接收姓名，用 input('未分配角色') 接收可选角色，用 output<string>() 声明选择事件。

  • input.required<T>() 表示必填，父组件漏传时开发期直接报错。
  • input(默认值) 表示可选，未传值时读取默认值。
  • output<T>() 返回事件发射器，emit 的载荷类型就是 T。

父模板用方括号传输入、圆括号接输出，事件回调里的 $event 即 emit 出来的值。

1.4 内容投影：让子组件决定位置 ​

<ng-content /> 是占位槽：父组件写在子组件标签之间的内容，会渲染到这个位置。投影内容属于父组件的模板上下文，表达式只能访问父组件状态；子组件只负责位置与样式。这适合传入任意标记片段，而 input() 适合传入一个数据值。

4. 代码拆解 ​

4.1 根组件的状态与派生数据 ​

ts
// 文件：src/app/app.ts（节选：省略 import、@Component 与 Member 接口）
export class App {
  protected readonly members = signal<Member[]>([
    { id: 1, name: '林晚', role: '前端工程师', score: 96 },
    { id: 2, name: '周野', role: '全栈工程师', score: 88 },
    { id: 3, name: '陈墨', role: '技术负责人', score: 92 },
  ]);
  protected readonly view = signal<'all' | 'top'>('all');
  protected readonly selected = signal('尚未选择成员');
  protected readonly visibleMembers = computed(() =>
    this.view() === 'top'
      ? this.members().filter((member) => member.score >= 90)
      : this.members(),
  );

  protected onSelect(name: string): void {
    this.selected.set(name);
  }
}

members 用泛型 signal<Member[]> 声明（元素含 id、name、role、score），有完整类型检查；view 用联合字面量限制取值。visibleMembers 是 computed：它读取 view 与 members，任一变化都会让缓存失效，输入不变时不会重复过滤。onSelect 接收子组件 emit 的姓名并写入 selected。

4.2 模板里的列表绑定 ​

app.html 用 @for 直接遍历 visibleMembers()，父组件不需要手动订阅。track member.id 把每张卡片与成员 id 绑定，(select)="onSelect($event)" 把子组件载荷交给父组件方法。模板末尾还有一个带 aria-live="polite" 的段落，用来播报当前选择，方便屏幕阅读器用户感知变化。

4.3 子组件的输入、输出与投影 ​

ts
// 文件：src/app/user-card.ts
import { Component, input, output } from '@angular/core';
import { Badge } from './badge';

@Component({
  selector: 'app-user-card',
  imports: [Badge],
  templateUrl: './user-card.html',
  styleUrl: './user-card.css',
})
export class UserCard {
  readonly name = input.required<string>();
  readonly role = input('未分配角色');
  readonly score = input(0);
  readonly select = output<string>();

  protected onSelect(): void {
    this.select.emit(this.name());
  }
}
html
<!-- 文件：src/app/user-card.html -->
<article class="user-card">
  <header>
    <h3>{{ name() }}</h3>
    <app-badge [hot]="score() >= 90">{{ score() }} 分</app-badge>
  </header>
  <p class="role">{{ role() }}</p>
  <button type="button" (click)="onSelect()">选择该成员</button>
</article>

UserCard 在 imports 中声明 Badge，才能在自己的模板里使用 app-badge。徽章标签之间的分数文本由 UserCard 提供，Badge 模板里的 <ng-content /> 负责渲染。Badge 只有 hot 一个输入，模板用 [class.badge--hot] 在分数达到 90 时切换高亮。

6. 练习 ​

  1. 新增成员并验证筛选：加入 { id: 4, name: '顾言', role: '测试工程师', score: 78 }。验收标准：全部视图 4 条，高分视图仍为 2 条，选中该成员后底部显示“顾言”。
  2. 补齐两位成员的分支：为 @switch 增加 @case (2)，文案为“恰好两位成员”。验收标准：全部视图 3 条走默认分支，高分视图 2 条命中新分支。
  3. 增加可选备注：给 UserCard 添加 note = input('') 并在卡片中显示。验收标准：只给一位成员传 note，其余卡片不报错且显示空字符串。
  4. 输出成员 id：给 UserCard 增加 readonly id = input.required<number>()，把 select 改为 output<number>() 并 emit this.id()；父组件传入 member.id，App 中据 id 查找姓名。验收标准：点击卡片后底部显示正确姓名，类型检查通过。

7. 自测 ​

1. @for 为什么必须有 track？

渲染器需要知道每一行对应哪份数据。track 提供稳定身份，列表增删或排序时才能复用正确的 DOM 与组件实例。缺省时 Angular 22 会直接报错，避免隐式使用索引造成状态错位。

2. input.required 与 input(默认值) 的区别是什么？

两者都返回只读 signal。required 版本没有默认值，父组件漏传会在开发期报错，适合契约中不可缺的字段；带默认值的版本可省略绑定，适合有合理兜底的配置项。

3. output() 与原生 DOM 事件是一回事吗？

不是。output() 是组件自定义事件，父模板通过同名事件绑定接收，载荷由 emit 决定，类型由泛型约束。原生事件来自真实 DOM 节点，$event 是 Event 或其子类型。

本章小结 ​

  • @for 依赖稳定的 track，@empty 负责空集合兜底；@switch 适合严格相等的枚举分支。
  • signal 输入用 input() / input.required() 声明，读取时必须调用；输出用 output() 加 emit。
  • computed 把筛选等派生逻辑集中到类中，模板保持简单且可缓存。
  • <ng-content /> 让子组件决定投影内容的落点，适合布局型组件。
