10 · 无障碍与国际化 ​

所属：第五篇 · 深度　配套示例：i18n-a11y

学习目标 ​

  • 对比运行时词典与 Angular 内置 i18n 的适用边界，能按产品约束做出选择
  • 用 signal 驱动语言切换，让可见文案与 aria-* 属性同步更新
  • 实现跳过导航、aria-live 状态播报与 aria-pressed 切换按钮
  • 打开和关闭对话框时正确移动焦点，并支持 Esc 关闭
  • 用 Intl 系列 API 处理数字、日期与复数，而不是手拼字符串
  • 能配置内置 i18n 的抽取与多语言构建，并让 locale data 与 RTL 真正生效

1. 两种国际化路线 ​

Angular 提供两条路线，差别不在语法，而在翻译发生的时刻。

运行时词典把所有文案放进对象，用 signal 记录当前语言，模板通过服务读取：

ts
// 文件：src/app/i18n.service.ts
const DICT = {
  zh: { title: '无障碍与国际化', saved: '已保存' },
  en: { title: 'Accessibility & i18n', saved: 'Saved' },
} as const;

type DictKey = keyof (typeof DICT)['zh'];

@Injectable({ providedIn: 'root' })
export class I18nService {
  readonly locale = signal<Locale>('zh');
  t(key: DictKey): string {
    return DICT[this.locale()][key];
  }
}

as const 保留字面量类型，DictKey 因此是 'title' | 'saved' 这样的联合类型，拼错 key 会在编译期报错。t() 读取 locale()，模板求值时自动建立依赖。

内置 i18n 则在模板上标注可翻译文本，构建期抽取，再为每种语言各生成一份产物：

html
<h1 i18n="站点标题|首页主标题@@home.title">订单管理</h1>
<button type="button" i18n="@@home.submit">提交</button>
bash
# 抽取模板中的 i18n 标记，生成 XLIFF 2.0 文件
ng extract-i18n --output-path src/locale --format=xlf2

在构建配置中声明 "localize": ["zh-Hans", "en-US"] 后，CLI 会读取翻译文件并输出多个语言版本。

维度运行时词典内置 i18n
切换语言页面内即时切换换产物或换 URL
首屏体积所有语言都进包每份产物只含一种语言
适用场景工具类应用、演示页面向公众、SEO 敏感站点

示例选择运行时词典，因为它要在 Playground 里即时演示切换；若产品要求「URL 决定语言、首屏只加载一种语言」，内置 i18n 更合适。内置路线依赖 @angular/localize，$localize 标签模板还能翻译 TS 中的字符串。

2. 机制拆解 ​

2.1 语言状态就是一个 signal ​

ts
readonly locale = signal<Locale>('zh');

setLocale(locale: Locale): void {
  this.locale.set(locale);
}

模板里每次 t(...) 都会读取 locale()，因此 setLocale 后所有调用点一起刷新，包括 [attr.aria-label] 与 [attr.aria-pressed]。为了让读屏正确发音，还应同步根元素的 lang；示例为突出焦点管理没有实现，练习中会补上。

2.2 焦点是键盘用户的坐标 ​

ts
protected openDialog(): void {
  this.dialogOpen.set(true);
  // 打开后把焦点移入对话框，键盘用户不会迷失位置
  setTimeout(() => this.dialogInput?.nativeElement.focus());
}

protected closeDialog(): void {
  this.dialogOpen.set(false);
  // 关闭后焦点回到触发按钮
  this.trigger?.nativeElement.focus();
}

打开时先改 signal，再等 DOM 出现后聚焦输入框；关闭时把焦点还给触发按钮。若省略归还，焦点会落到 body，键盘用户必须从头重新 Tab。示例用 setTimeout 等待异步变更检测完成，生产代码可改用 afterNextRender。

2.3 对话框语义与 Esc ​

html
<section class="dialog" role="dialog" aria-modal="true"
  [attr.aria-label]="i18n.t('dialogTitle')" (keydown)="onDialogKeydown($event)">

role="dialog" 加 aria-modal="true" 告诉辅助技术其余内容暂时不可交互；aria-label 提供可读名称。keydown 判断 Escape 关闭，遮罩点击也可关闭。必须说明：示例没有实现完整的焦点陷阱，Tab 仍可能移出对话框；生产应用应使用原生 <dialog> 的 showModal() 或 CDK Dialog。

2.4 aria-live 只播报变化 ​

html
<p class="status" role="status" aria-live="polite">
  @if (saved()) { {{ i18n.t('saved') }} }
</p>

role="status" 隐含 aria-live="polite"，读屏会在当前朗读结束后播报变化。关键在于容器始终存在，只是内部文本从空变为「已保存」；若整个容器由条件块创建，部分读屏会错过首次播报。

2.5 跳过导航与切换按钮 ​

html
<a class="skip" href="#main">{{ i18n.t('skip') }}</a>
<main id="main" class="page">
  <h1>{{ i18n.t('title') }}</h1>
</main>
css
.skip { position: absolute; left: -9999px; top: 8px; }
.skip:focus { left: 12px; }

跳过链接平时移出视口，聚焦时出现，用户按 Enter 直接跳到主内容区。目标元素加 tabindex="-1" 能让焦点转移更一致。语言按钮用 aria-pressed 表示选中状态，不能只靠背景色；按钮文案用各自语言书写，方便用户识别。数字、日期与复数则交给 Intl.NumberFormat、Intl.DateTimeFormat 与 Intl.PluralRules，不要在词典里拼格式。

2.6 内置 i18n 实跑：locale data、ICU、$localize 与 RTL ​

内置路线不能只停留在模板标注，它依赖三块构建配置：

  1. 项目级 i18n.sourceLocale 声明源语言，locales 指向每种语言的翻译文件；
  2. build.options.localize: true 让一次构建为每个语言各产出一份完整产物；
  3. 非 en-US 语言必须注册 locale data，否则 DatePipe、CurrencyPipe 找不到该语言的数据。
json
// 文件：angular.json（项目级）
"i18n": {
  "sourceLocale": "zh-Hans",
  "locales": {
    "en": "src/locale/messages.en.xlf",
    "ar": "src/locale/messages.ar.xlf"
  }
}
json
// 文件：angular.json（build options）
"options": { "localize": true }

先用 CLI 抽取源消息，再在 XLF 里填 target：

bash
ng extract-i18n --format=xlf2 --output-path src/locale --out-file messages.xlf

构建后产物按语言分目录：dist/i18n-build/browser/{zh-Hans,en,ar}/。Angular 会把每份 index.html 的 lang、base href 写成对应语言，阿拉伯语还会自动带上 dir="rtl"——这来自 locale data，而不是手写判断。

模板里的 ICU 表达式在翻译文件中原样保留变量名与占位符：

html
<p i18n="@@cart.plural">
  {count(), plural,
    =0 {购物车是空的}
    =1 {只有 1 件商品}
    other {共 {{count()}} 件商品}}
</p>

抽取结果为 {VAR_PLURAL, plural, =0 {...} =1 {...} other {... <ph id="0" equiv="INTERPOLATION"/> ...}}，翻译时只改文案，VAR_PLURAL 与 <ph> 必须保留。TS 中的字符串用 $localize 标注：

ts
// 文件：src/app/app.ts
protected summary(count: number): string {
  return $localize`:@@order.summary:订单号 A-1024，共 ${count} 件商品`;
}

它需要两件事配合：@angular/localize/init 放进 polyfills，tsconfig 的 types 加入 @angular/localize（否则 $localize 没有全局类型）。locale data 则在启动时注册：

ts
// 文件：src/main.ts
import { registerLocaleData } from '@angular/common';
import localeAr from '@angular/common/locales/ar';
registerLocaleData(localeAr);

RTL 布局的细节是：方向由根元素 dir 决定，组件样式应使用逻辑属性（margin-inline-start、inset-inline-start），而不是 margin-left。这样同一份 CSS 在 ltr 与 rtl 下都能正确镜像。

3. 可运行示例 ​

双语无障碍界面

运行时语言切换、跳过导航、焦点管理与 aria-live。

示例会在滚动到此处时加载，首次启动需要等待依赖安装。

3.1 建议先改这里 ​

  1. 切到 English，用 Tab 依次走「跳过链接 → 语言按钮 → 打开对话框」。预期：跳过链接出现、按钮有清晰焦点环、对话框打开后光标在姓名输入框。
  2. 删掉 status 段落上的 aria-live="polite" 再保存。预期：视觉不变，但读屏不再主动播报「已保存」。
  3. 注释掉 closeDialog 里的 this.trigger?.nativeElement.focus()。预期：按 Esc 后焦点落回页面顶部，继续 Tab 不再从触发按钮开始。

3.2 构建版示例：三份语言产物 ​

内置 i18n 多语言构建

构建期抽取翻译，按 zh-Hans / en / ar 生成三份产物，含 ICU 复数、$localize 与 RTL。

该示例需要本地运行，不在浏览器沙箱内。

在仓库根目录执行 pnpm --filter i18n-build build && pnpm --filter i18n-build preview， 然后访问 http://localhost:4600/zh-Hans/。

这个示例走内置路线，构建后得到 zh-Hans、en、ar 三份独立产物。三份产物共享同一套模板与 TS，但文案、ICU 复数分支、日期与货币格式都不同；ar 产物根元素带 dir="rtl"，卡片与按钮自动镜像。

bash
# 构建三份产物并校验 lang/dir、资源与翻译是否真的进了 bundle
pnpm --filter i18n-build build
pnpm --filter i18n-build verify
# 本地静态预览，切换 URL 即可切换语言
pnpm --filter i18n-build preview

打开 http://localhost:4600/zh-Hans/、/en/、/ar/ 对比即可。需要先改这里：

  1. 改 src/locale/messages.en.xlf 的 target，重新构建。预期：en 产物文案变化，ar 与 zh-Hans 不受影响。
  2. 删掉 messages.ar.xlf 中 cart.plural 的某个 =1 分支再构建。预期：构建报 ICU 结构不一致的警告/错误，提醒翻译不能随意删减分支。
  3. 在 app.css 里把 margin-inline-start 改成 margin-left，切到 ar。预期：布局不再镜像，说明逻辑属性才是 RTL 的正确姿势。

4. 代码拆解 ​

4.1 类型约束、焦点与 Esc ​

Locale 限制可选语言，DictKey 从中文词典推导；两份词典结构必须一致，漏写或拼错 key 都会被 TypeScript 拦下。locale 属性只读，写入只能通过 setLocale，便于以后加入保存偏好、更新 lang 等副作用。

ts
// 文件：src/app/app.ts
@ViewChild('trigger') private trigger?: ElementRef<HTMLButtonElement>;
@ViewChild('dialogInput') private dialogInput?: ElementRef<HTMLInputElement>;

protected onDialogKeydown(event: KeyboardEvent): void {
  if (event.key === 'Escape') {
    this.closeDialog();
  }
}

protected save(): void {
  this.saved.set(true);
  this.closeDialog();
}

两个 ViewChild 引用模板中的 #trigger 与 #dialogInput。保存时先写 saved 再关闭，让状态播报与焦点归还发生在同一次交互中。

4.2 模板中的无障碍属性 ​

html
<!-- 文件：src/app/app.html -->
<div class="langs" role="group" aria-label="Language">
  <button type="button" [attr.aria-pressed]="i18n.locale() === 'zh'" (click)="i18n.setLocale('zh')">中文</button>
  <button type="button" [attr.aria-pressed]="i18n.locale() === 'en'" (click)="i18n.setLocale('en')">English</button>
</div>

<p class="status" role="status" aria-live="polite">
  @if (saved()) { {{ i18n.t('saved') }} }
</p>

5. 常见坑 ​

现象原因处理
切换语言后对话框读屏名称仍是旧语言只翻译了可见标题，漏了 aria-label所有面向用户与辅助技术的文本都走同一词典
读屏从不播报保存成功状态容器随条件创建，出现时已错过变化保留常驻容器，只在内部切换文本
键盘用户按 Esc 后迷失位置关闭时未归还焦点在关闭逻辑中显式聚焦触发元素
跳过链接无法用 Tab 到达用 display: none 或 visibility: hidden 隐藏移出视口定位，聚焦时移回
语言按钮选中态只有颜色差异只加 class 未暴露状态增加 aria-pressed，并保留可见焦点样式

6. 练习 ​

  1. 同步文档语言：在 setLocale 中更新 document.documentElement.lang，初始化时也设置一次。 验收：切换语言后，元素面板中 html 标签的 lang 在 zh 与 en 之间变化。
  2. 补全焦点陷阱：让 Tab 在对话框内循环，Shift + Tab 反向循环，关闭后仍归还焦点。 验收：不借助鼠标，连续 Tab 十次焦点不离开对话框。
  3. 本地化金额与日期：新增一条订单数据，用 Intl.NumberFormat 与 Intl.DateTimeFormat 展示。 验收：中文显示人民币与本地日期格式，切换英文后格式随之变化。

7. 自测 ​

1. 为什么示例用运行时词典而不是内置 i18n？

示例需要在页面内即时切换语言来演示无障碍行为。内置 i18n 在构建期确定语言，每种语言生成独立产物，切换意味着换 URL 或重新加载；运行时词典由 signal 驱动，切换成本低，但所有语言文案都会进入包体。

2. 对话框打开后为什么不能立刻聚焦输入框？

signal 写入只是安排了一次变更检测，模板尚未渲染出新节点，此时查询输入框会得到空值。示例用 setTimeout 等待渲染完成，afterNextRender 是更明确的表达方式。

3. 只翻译可见文本够不够？

不够。aria-label、title、alt、表单错误提示都属于用户可感知文本，必须与可见文案使用同一份词典，否则语言切换后辅助技术仍朗读旧语言。另外，role="status" 已隐含礼貌播报，不必再叠加 aria-live="assertive"。

本章小结 ​

  • 运行时词典适合即时切换，内置 i18n 适合按语言独立构建，选择取决于产品约束。
  • 把语言放进 signal，可见文案与 aria-* 属性会一起刷新。
  • 焦点管理要成对出现：打开移入、关闭归还，Esc 只是关闭方式之一。
  • aria-live 依赖常驻容器，跳过链接依赖可聚焦的隐藏方式。
  • 数字、日期与复数交给 Intl，不要让翻译人员手拼格式。
