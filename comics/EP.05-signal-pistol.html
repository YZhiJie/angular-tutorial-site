EP.05 Signal 就是信号枪 ​

对应正文：05-signals（1 状态是依赖图 / 2 四种原语行为 / 3 可运行示例 / 4 代码拆解）· 配套示例：signals-lab · Playground id：signals-lab

剧情回顾 ​

  • 第 1 格：标签君改了 total 字段但模板不刷新——哦原来它是普通字段不是 signal！signal 才是 zoneless 下的刷新通道。
  • 第 2 格：码叔把 signal / computed / effect / linkedSignal 四种原语摆出来：signal 唯一可写入口，computed 惰性带缓存，effect 自动订阅副作用，linkedSignal 可写可跟随。
  • 第 3 格：像素酱画出 signal.set() 的完整触发时间线：写入 → 调度器标记依赖者 → computed 重算 → effect 同步 → 模板刷新。还特别提醒 effect 读写分离，别写回环。
  • 第 4 格：码叔结案——源信号唯一、派生全靠 computed、effect 只做同步副作用。三个坑点：普通字段不改、computed 惰性不推值、effect 别读写同一个 signal。

知识点拆解 ​

第 1 格 · 普通字段 vs signal ​

zoneless 下 Angular 不再追任何属性写入。只有 signal 的 .set() / .update() 会通知调度器：

ts
// ❌ 普通字段——改了没人知道
class Cart { total = 0; }
this.cart.total = 1256;  // 模板不刷新

// ✅ signal——写入即通知
const price = signal(199);
const quantity = signal(2);
price.set(299);  // 调度器立刻标记依赖者

关键区别：signal 是「值 + 依赖关系」的合体。读取时登记"谁依赖了我"，写入时逐个通知。

第 2 格 · 四种原语分工 ​

原语可写行为典型用途
signal(init)✅唯一写入入口源状态、表单值
computed(fn)❌惰性 + 带缓存的派生总价、折后价等派生数据
effect(fn)—自动订阅副作用日志、localStorage 同步
linkedSignal(fn)✅可写但跟随源信号草稿、可临时覆盖的值
ts
const price = signal(199);                    // 源信号
const total = computed(() => price() * qty()); // 纯派生
const log = signal<string[]>([]);

effect(() => {                                 // 副作用
  log.update(l => [...l.slice(-4), total() + '元']);
});

const draft = linkedSignal(() => quantity());  // 草稿可写，源变则重置
draft.set(7);   // 临时偏离
quantity.set(5); // 源变 → draft 自动回到 5

安全第一：effect 的读写集合不能相交——读完 total 不能再写 total。

第 3 格 · 触发顺序时间线 ​

price.set(299)
  ↓
调度器标记所有依赖者（不立即执行）
  ↓
computed('total') 下次被读时重算 → 缓存失效
  ↓
effect 检测到依赖变化 → 同步执行一次
  ↓
模板下一次变更检测 → 读取 computed → 拿到新值 → DOM 更新

computed 的惰性是性能关键——如果模板没读到 total，它就永远不会被重算。缓存只要依赖没变就直接命中。

第 4 格 · 信号枪守则 ​

zoneless 下哪些操作会触发刷新？

  1. signal 写入（set / update）
  2. 模板事件回调
  3. 显式 markForCheck()
  4. 异步管道发射值

除此之外，任何你直接改对象属性、往数组 push 的操作都不会被感知。

Signal vs BehaviorSubject

维度signalBehaviorSubject
初始值必须必须
读取count().value 或 subscribe
自动依赖收集✅ 模板/effect/computed❌ 需手动 pipe
模板支持直接用 count()需 async 管道或转 signal
错误处理无（自己 try/catch）catchError 等操作符

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 修改对象属性后页面不更新 → 用 set/update 替换整个值，或改为不可变更新；
  2. 以为 computed 会主动推送新值 → computed 是惰性的，只有被读才计算；
  3. effect 日志无限增长或重复 → effect 读写同一个 signal 形成回环；
  4. 草稿值在源信号变化后被覆盖 → 这是 linkedSignal 的预期行为，要永久保留就另建独立 signal；
  5. 模板里调用方法导致频繁计算 → 每次检查都执行方法，用 computed 缓存派生结果；
  6. 在 effect 中发 HTTP 请求 → effect 没有取消语义，用 RxJS 或资源类 API。

自测 3 题（含答案） ​

  1. computed 和普通 getter 的核心区别是什么？ —— computed 登记依赖并在依赖不变时返回缓存值，只有依赖变化后的首次读取才重新计算；普通 getter 每次访问都执行。模板中用 computed 能避免重复计算，也能作为稳定的依赖节点参与后续派生。

  2. 为什么不能在 effect 里写回它自己读取的 signal？ —— effect 的调度依据就是"读取过的 signal 发生变化"。写入同一个 signal 会让 effect 再次满足运行条件，形成回环，轻则日志重复、重则不断调度。正确做法是把副作用目标做成独立 signal，或者用 untracked 读取不希望出现在依赖图里的值。

  3. zoneless 下，哪些操作能触发视图刷新？ —— 模板读取的 signal 变化、模板事件回调执行、调用 markForCheck()、异步管道发射值都会触发调度。直接修改对象属性或数组内容不在其中，所以状态更新要经过 signal 的写入 API。
