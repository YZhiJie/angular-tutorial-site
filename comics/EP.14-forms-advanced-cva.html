EP.14 表单的三件武器 ​

对应正文：14-forms-advanced（2 FormArray / 3 CVA / 4 异步校验 / 7 常见坑）· 配套示例：routing-form

剧情回顾 ​

  • 第 1 格：标签君要给手机号做「想加几个加几个」，还要给密码接一个自定义强度控件。直接改 FormArray 的底层数组，校验与脏值状态都不更新。
  • 第 2 格：码叔列出三件武器的协议——FormArray 的 push / removeAt、CVA 的四个方法、异步校验的 PENDING 状态。
  • 第 3 格：像素酱看到校验顺序：同步校验先跑，异步校验只在同步通过后执行；等待期间控件是 PENDING，不是 VALID。
  • 第 4 格：码叔结案——FormArray 管结构，CVA 管协议，异步校验管时机；跨字段规则要挂在 FormGroup 上。

知识点拆解 ​

第 1 格 · FormArray 不是普通数组 ​

FormArray 的每个元素都是独立控件，增删要调用 API，不能直接改底层数组：

ts
protected addPhone(): void {
  this.form.controls.phones.push(this.fb.nonNullable.control(''));
}

protected removePhone(index: number): void {
  this.form.controls.phones.removeAt(index);
}

模板里 formControlName 用 $index，因为 FormArray 的键就是数字下标：

html
@for (phone of form.controls.phones.controls; track $index) {
  <input [formControlName]="$index" autocomplete="tel" />
}

第 2 格 · CVA 的四个方法 ​

自定义控件要接进响应式表单，必须实现 ControlValueAccessor：

方法作用
writeValue(value)表单把值推给控件
registerOnChange(fn)控件值变化时通知表单
registerOnTouched(fn)控件失焦时通知表单
setDisabledState(isDisabled)响应表单的 disable()

内部可以用 signal 保存展示状态，但对外必须调用 onChange，否则表单模型不会更新。

第 3 格 · 异步校验的三种状态 ​

同步校验器先跑，异步校验器只在同步通过后执行；异步期间控件状态是 PENDING：

ts
validators: [Validators.required],
asyncValidators: [usernameTaken()],
updateOn: 'blur',

模板必须同时处理 pending、具体错误与「还没触碰」：

html
@if (form.controls.username.pending) {
  <p role="status">正在检查用户名是否可用...</p>
}
@if (form.controls.username.touched && form.controls.username.hasError('usernameTaken')) {
  <p role="alert">这个用户名已经被占用。</p>
}

第 4 格 · 跨字段校验挂在哪里 ​

「结束时间必须晚于开始时间」不适合拆成两个字段级校验器，应挂在 FormGroup 上读取兄弟控件：

ts
this.fb.group({
  start: [''],
  end: [''],
}, { validators: [dateRangeValidator] });

这样错误显示在组级别，也不会因为字段更新顺序产生假阴性。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 直接改 FormArray 底层数组 → 校验与脏值状态不更新，改走 push / removeAt；
  2. 把 PENDING 当 VALID → 异步结果还没回来就允许提交；
  3. 跨字段规则挂到单字段 → 更新顺序会造成假阴性，挂到 FormGroup；
  4. 异步校验不加防抖 → 每次按键都发请求，updateOn: 'blur' 或防抖。

自测 3 题（含答案） ​

  1. 为什么不能直接 push 到 FormArray 的底层数组？——FormArray 的元素是独立 AbstractControl，只有通过 push / removeAt 才会注册控件、更新校验与脏值状态；直接改数组绕过了这套机制。
  2. CVA 的 registerOnChange 与 writeValue 有什么区别？——writeValue 是表单 → 控件的单向推送；registerOnChange 保存控件 → 表单的通知回调，控件内部值变化时必须调用它。
  3. 异步校验期间为什么不能显示「可用」？——此时状态是 PENDING，结果尚未确定；提前显示「可用」会让用户在结果回来后继续提交已失效的值。
