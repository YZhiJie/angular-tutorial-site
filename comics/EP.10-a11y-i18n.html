EP.10 让所有人都能用 ​

对应正文：10-a11y-i18n（1 两种国际化路线 / 2 机制拆解 / 3 可运行示例 / 4 代码拆解 / 5 常见坑）· 配套示例：i18n-a11y

剧情回顾 ​

  • 第 1 格：像素酱发现页面上一个图标按钮，屏幕阅读器读出来就是"按钮"两个字——aria-label 被漏掉了。aria-label / aria-describedby / aria-live 不是"可选功能"，而是读屏用户的全部信息。
  • 第 2 格：码叔展示两种国际化路线——运行时词典用 signal<Locale> 即时切换，所有语言进包；内置 $localize + ICU 复数格式在构建期抽取，每种语言独立产物。两者都能让模板里 t() 随 locale() 刷新，aria- 属性跟着一起变*。
  • 第 3 格：标签君做实证——同一组件切到中文、英文、阿拉伯文三语，数字和日期交给 Intl API，阿拉伯文自动 RTL。
  • 第 4 格：码叔结案——可见文本、aria- 属性、焦点状态*，三种用户一套词典。焦点管理成对出现：打开移入、关闭归还。

知识点拆解 ​

第 1 格 · aria 属性就是读屏的眼睛 ​

ts
// 运行时词典 + 类型约束
const DICT = {
  zh: { title: '无障碍与国际化', saved: '已保存' },
  en: { title: 'Accessibility & i18n', saved: 'Saved' },
} as const;

type DictKey = keyof (typeof DICT)['zh'];

@Injectable({ providedIn: 'root' })
export class I18nService {
  readonly locale = signal<Locale>('zh');
  t(key: DictKey): string {
    return DICT[this.locale()][key];
  }
}

as const 保留字面量类型，DictKey 因此是 'title' | 'saved' 联合类型，拼错 key 编译期报错。t() 读取 locale()，模板求值时自动建立依赖。

第 2 格 · 两种 i18n 路线 ​

维度运行时词典内置 i18n
切换语言页面内即时切换换产物或换 URL
首屏体积所有语言都进包每份产物只含一种语言
适用场景工具类应用、演示页面向公众、SEO 敏感站点

内置 i18n 标注方式：

html
<h1 i18n="站点标题|首页主标题@@home.title">订单管理</h1>
<button type="button" i18n="@@home.submit">提交</button>

第 3 格 · 焦点管理要成对 ​

ts
protected openDialog(): void {
  this.dialogOpen.set(true);
  // 等 DOM 出现后聚焦输入框
  setTimeout(() => this.dialogInput?.nativeElement.focus());
}

protected closeDialog(): void {
  this.dialogOpen.set(false);
  // 焦点归还触发按钮
  this.trigger?.nativeElement.focus();
}

signal 写入只是安排了一次变更检测，模板尚未渲染新节点，此时查询会得到空值。setTimeout 等待渲染完成，生产代码用 afterNextRender。

第 4 格 · aria-live 只播报变化 ​

html
<p class="status" role="status" aria-live="polite">
  @if (saved()) { {{ i18n.t('saved') }} }
</p>

关键：容器必须常驻，只在内部切换文本。若整个容器由条件块创建，部分读屏会错过首次播报。数字、日期、复数交给 Intl.NumberFormat / Intl.DateTimeFormat / Intl.PluralRules，不要让翻译人员手拼格式。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 切换语言后对话框读屏名称还是旧语言 → 只翻译了可见标题，漏了 aria-label，所有面向用户与辅助技术的文本都走同一词典；
  2. 键盘用户按 Esc 后迷失位置 → 关闭时未归还焦点，在关闭逻辑中显式聚焦触发元素；
  3. 跳过链接无法用 Tab 到达 → 用 display: none 或 visibility: hidden 隐藏，应用移出视口定位；
  4. 语言按钮选中态只有颜色差异 → 只加 class 未暴露状态，增加 aria-pressed。

自测 3 题（含答案） ​

  1. 为什么示例用运行时词典而不是内置 i18n？——需要页面内即时切换语言来演示无障碍行为。内置 i18n 在构建期确定语言，每种语言独立产物，切换意味着换 URL 或重新加载。
  2. 对话框打开后为什么不能立刻聚焦输入框？——signal 写入只是安排一次变更检测，模板尚未渲染出新节点，此时查询输入框会得到空值，用 setTimeout 或 afterNextRender 等待渲染完成。
  3. 只翻译可见文本够不够？——不够。aria-label、title、alt、表单错误提示都必须与可见文案使用同一份词典，另外 role="status" 已隐含礼貌播报，不必叠加 aria-live="assertive"。
