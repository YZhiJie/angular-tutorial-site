EP.02 模板里那些糖 ​

对应正文：02-template-syntax（1 模板语法与组件通信的三个支点 / 2 动手步骤 / 3 可运行示例 / 4 代码拆解 / 5 常见坑 / 7 自测）· 示例：examples/template-syntax · Playground id：template-syntax

剧情回顾 ​

  • 第 1 格：标签君兴冲冲写 @for (member of list()) { }，编译器直接炸了——Angular 22 强制显式 track，给每行一个稳定身份。
  • 第 2 格：码叔拆解编译器：@if / @for / @switch 不是指令，是模板 AST 节点，编译器直接生成结构指令——不需要在 imports 里声明 NgIf / NgFor。
  • 第 3 格：像素酱展示 input() / input.required() / output() 的组合拳：父组件 [name]="member.name" 传输入，子组件 (select)="onSelect($event)" 接输出，$event 就是 emit 的载荷。
  • 第 4 格：码叔结案——模板是声明式契约，编译器替你写指令，别用 $index 偷懒当 track。

知识点拆解 ​

第 1 格 · @for 必须有 track ​

track 表达式告诉渲染器每一行的"身份"——列表增删或排序时，Angular 才能复用正确的 DOM 节点和组件实例：

html
<!-- ✅ 数据自身稳定身份 -->
@for (member of visibleMembers(); track member.id) {
  <app-user-card [name]="member.name" />
} @empty {
  <p class="empty">没有符合条件的成员。</p>
}
  • 写 track member.id 等唯一字段，列表重排时不会造成卡片状态错位；
  • 用 track $index 等于说"第一行永远是第一行"，删除中间一项后续状态全错；
  • 空集合靠 @empty { } 兜底，不需要额外判空。

第 2 格 · 新控制流是编译期糖 ​

@if / @for / @switch 与 *ngIf / *ngFor 本质上是同一套底层机制——前者是 Angular 17+ 起的模板 AST 扩展语法，编译器直接把它翻译成结构性指令：

新语法编译结果需要导入
@if (ok()) { }*ngIf="ok()"❌ 不需要
@for (x of list(); track x.id) { }*ngFor + track❌ 不需要
@switch (v) { @case (0) { } }*ngSwitch 全家桶❌ 不需要

混用新旧语法不会报错，但建议项目里统一用新控制流——代码更干净，也不会漏写 imports。

第 3 格 · input() / output() 通信 ​

Angular 17+ 把组件契约 signal 化了：

ts
// 子组件：声明输入输出
readonly name = input.required<string>();   // 必填 signal
readonly role = input('未分配角色');          // 可选 signal，带默认值
readonly select = output<string>();          // 事件发射器

// 子组件方法里这样发事件：this.select.emit(this.name());

模板读取 signal 输入时必须加括号 { { name() } }，不是 { { name } }（后者显示函数源码）。父组件用方括号传值 [name]="member.name"，用圆括号接事件 (select)="onSelect($event)"，$event 就是 emit 出来的载荷。

第 4 格 · 组件通信还有一张牌：ng-content ​

input() 传数据值，output() 发事件，但父组件想传一段任意 HTML 片段怎么办？用 <ng-content />：

html
<!-- 父组件 -->
<app-badge [hot]="score() >= 90">{{ score() }} 分</app-badge>

<!-- 子组件模板里 -->
<article>
  <ng-content />   <!-- 父组件写在标签之间的内容渲染到这里 -->
</article>

投影内容属于父组件的模板上下文，里面的表达式访问父组件状态；子组件只决定位置和样式，不决定内容。适合卡片、弹窗、徽章这类布局型组件。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. @for 漏写 track → Angular 22 强制显式声明，用数据自身的唯一 id，别偷懒写 $index；
  2. 删除中间项后卡片状态错位 → track $index 让行身份随位置变化，改用稳定 id；
  3. 子组件显示函数源码 → signal 输入在模板里必须加括号，写 name() 而不是 name；
  4. input.required 漏传导致运行时报错 → 补上绑定，或改为 input(默认值)；
  5. 子组件标签内内容不显示 → 子组件模板缺 <ng-content />，加占位槽。

自测 3 题（含答案） ​

  1. @for 为什么必须有 track？——渲染器需要知道每一行的身份，列表增删排序时才能复用正确的 DOM 与组件实例；Angular 22 强制显式声明以避免隐式索引造成的状态错位。
  2. input.required 与 input('未分配角色') 的区别是什么？——两者都返回只读 signal。required 版本没有默认值，父组件漏传会在开发期报错；带默认值的版本可省略绑定，适合有合理兜底的配置项。
  3. <ng-content /> 和 input() 应该怎么选？——input() 传一个数据值，属于子组件可感知的契约；<ng-content /> 接受任意 HTML 片段，投影内容仍属于父组件上下文。数据传值用 input，布局插槽用投影。
