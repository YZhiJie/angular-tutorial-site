EP.15 信任边界 ​

对应正文：15-security（1 信任边界 / 2 自动净化 / 4 CSP / 5 Trusted Types / 8 常见坑）· 配套示例：i18n-a11y

剧情回顾 ​

  • 第 1 格：标签君把用户评论直接交给 bypassSecurityTrustHtml，评论里的 <img onerror> 被执行，页面弹窗。
  • 第 2 格：码叔画出信任边界——用户输入、接口、URL 都不可信；HTML、URL、STYLE、SCRIPT 各有对应的净化 context。
  • 第 3 格：像素酱对照两条路径：sanitize 保留 <b>、移除 onerror 与 <script>；bypass 则原样保留并执行。
  • 第 4 格：码叔结案——文本用插值、HTML 用净化、bypass 只给可信来源；CSP 与 Trusted Types 是第二道、第三道防线。

知识点拆解 ​

第 1 格 · 信任边界不是字符过滤 ​

来自用户、URL、接口、第三方脚本的数据都属于不可信输入；模板静态文案才可信。不可信数据进 DOM 前必须净化或验证：

ts
protected readonly safeHtml = computed(
  () => this.sanitizer.sanitize(SecurityContext.HTML, this.rawHtml()) ?? '',
);

<b> 会保留，onerror 会被移除。

第 2 格 · context 必须与输出位置匹配 ​

SecurityContext用途典型输出
HTML富文本片段移除脚本、事件属性与危险标签
URLhref / src危险协议变为 unsafe:
STYLE内联样式移除危险 CSS 表达式
SCRIPT脚本内容仅允许可信脚本
ts
this.sanitizer.sanitize(SecurityContext.URL, 'javascript:alert(1)');

用 HTML 的规则处理 URL，javascript: 链接仍然可点击。

第 3 格 · bypass 是声明，不是能力 ​

bypassSecurityTrust* 会跳过净化，只应出现在两种场景：内容来自完全可信的后端富文本服务，或已由独立净化库（如 DOMPurify）处理。即便如此，也要满足来源可追溯、规则持续更新、输出点有审计。

把 bypassSecurityTrustHtml 用在用户评论、昵称、聊天消息上，等同于关闭 XSS 防护。

第 4 格 · CSP 与 Trusted Types ​

净化解决「恶意内容进入 DOM」，CSP 解决「即使脚本进来了也别执行」：

http
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  object-src 'none';
  base-uri 'self';

Trusted Types 进一步要求危险 sink 只接受经过策略创建的 TrustedHTML。落地顺序：先 Report-Only 收集违规，再启用 require-trusted-types-for 'script'，最后把第三方库逐个纳入策略。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 对用户评论用 bypassSecurityTrustHtml → 等同关闭 XSS 防护，改用 sanitize 或 DOMPurify；
  2. URL 绑定用 HTML context → javascript: 仍可点击，必须用 SecurityContext.URL；
  3. CSP 一次性收得太死 → 生产白屏，先用 Report-Only 收集再收紧；
  4. 自定义指令直接拼 DOM 字符串 → 绕过 Trusted Types，通过策略创建 TrustedHTML；
  5. SSR 场景拼接用户数据 → 服务端绕过模板转义，必须复用同一套净化逻辑。

自测 3 题（含答案） ​

  1. 为什么「过滤坏字符」不足以防护 XSS？——攻击向量不止字符，还包括协议、属性与 DOM sink；正确做法是划清信任边界，按输出位置选择净化 context，并配合 CSP 与 Trusted Types。
  2. SecurityContext.URL 与 SecurityContext.HTML 有什么不同？——HTML 规则针对富文本片段，移除脚本与事件属性；URL 规则针对 href / src，把危险协议替换为 unsafe:。用错 context 会让危险 URL 通过。
  3. Trusted Types 解决的是什么问题？——它把 innerHTML 等危险 sink 限制为只接受策略创建的 TrustedHTML，让「忘记净化」从静默执行变成运行时错误。
