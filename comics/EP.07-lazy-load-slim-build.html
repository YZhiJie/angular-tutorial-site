EP.07 懒加载怎么瘦体积 ​

对应正文：07-build（1 首屏体积由引用关系决定 / 2 三种手段各管什么 / 3 可运行示例 / 4 代码拆解）· 配套示例：build-lab · Playground id：build-lab

剧情回顾 ​

  • 第 1 格：标签君发现首屏 2MB，RxJS 就占了 300KB，报表页明明没打开怎么也在主包里——原来用了 patch 模式和静态 import，打包器不会因为"写在不同文件"就自动拆包。
  • 第 2 格：码叔摆出三种手段：loadComponent 路由级懒加载按页面拆，@defer 区块级延迟加载，OnPush + signal 减少运行时检查（不直接减体积）。关键是静态 import 决定主包，动态 import() 才是分包边界。
  • 第 3 格：像素酱画出构建前后对比——2MB 砍到 980KB，Reports chunk 450KB 单独加载，Stats chunk 180KB 空闲时加载。还有 angular.json 里的预算配置，超 warning 警告、超 error 构建失败。
  • 第 4 格：码叔结案——首屏瘦不瘦，构建产物说了算，别凭感觉。三个坑点：@defer 里的组件块外也被 import 了、SPA fallback、OnPush 下原地改数组。

知识点拆解 ​

第 1 格 · 引用关系决定体积 ​

打包器看的是静态引用图，不是"文件位置"：

ts
// ❌ 静态 import → 进主包
import { Reports } from './reports';  // 无论你用不用它

// ✅ 动态 import → 独立 chunk
loadComponent: () => import('./reports').then(m => m.Reports)

RxJS patch vs pipeable：

ts
// ❌ patch 模式——一次性把所有操作符打包进来
import 'rxjs/add/operator/map';
import 'rxjs/add/operator/switchMap';
// 这俩 import 隐式注册了全部操作符的原型扩展

// ✅ pipeable——只打你 import 的那几个
import { map, switchMap, debounceTime } from 'rxjs/operators';

Angular CLI 从 v12 起默认禁用了 patch 模式，tree-shaking 才能正常工作。

第 2 格 · 三种手段各管什么 ​

手段粒度触发时机减小体积？
loadComponent / loadChildren路由页面路由匹配时✅ 是的
@defer (on idle/interaction/viewport)页面内区块浏览器空闲 / 点击 / 滚到视口✅ 是的
OnPush + signal组件内部输入变 / signal 变 / 模板事件❌ 减运行时检查
ts
// 路由级懒加载
{ path: 'reports', loadComponent: () => 
  import('./reports').then(m => m.Reports) }
html
<!-- 区块级延迟加载 -->
@defer (on idle) {
  <app-stats />
} @placeholder {
  <p>加载中...</p>
} @loading (minimum 300ms) {
  <p>正在下载...</p>
}

@defer 分包失效的常见原因：同一个组件在延迟块内外都被静态 import 了——打包器必须把它留在主包，否则块外代码无法启动。

第 3 格 · 预算把体积变成可失败的指标 ​

json
// angular.json → production 配置
{
  "budgets": [
    { "type": "initial", 
      "maximumWarning": "500kB", "maximumError": "1MB" },
    { "type": "anyComponentStyle", 
      "maximumWarning": "4kB", "maximumError": "8kB" }
  ],
  "outputHashing": "all"
}
  • initial：首屏入口 + 同步依赖的总体积，防主包膨胀
  • anyComponentStyle：单组件样式体积，防某个组件塞巨量 CSS
  • outputHashing: "all"：产物文件名加内容哈希，配合长期缓存——内容不变则文件名不变

构建结果是判断有没有拆成功的唯一依据：

bash
npm run build
ls -la dist/build-lab/browser/*.js
# 你会看到 main.xxxxx.js、reports.xxxxx.js、stats.xxxxx.js
# 打开 main.js，确认 Reports 组件不在里面

第 4 格 · OnPush 到底减什么 ​

OnPush 不改变打包结果，它减少的是运行时变更检测的范围与频率：

ts
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
  // ...
})
export class Stats {
  private readonly samples = signal([12, 18, 9]);
  protected readonly total = computed(() => 
    this.samples().reduce((s, v) => s + v, 0));
}

在 zoneless + OnPush 下，组件只在三种情况被检查：

  1. 输入属性引用变化
  2. 模板事件触发
  3. 组件自己读取的 signal 变化

坑：原地修改数组 arr.push(x) 不会触发检查——signal 里放的是数组引用，引用没变。要用 .update(arr => [...arr, x]) 产生新引用。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 统计卡片一打开就出现 → on idle 在空闲时很快触发，属正常行为；要明确时机就换 on interaction 或 on viewport；
  2. placeholder 从来没显示过 → 触发条件立即满足或加载极快，不要当作稳定可见的 UI；
  3. 报表页仍然打进主包 → 其他模块静态引用了 Reports，检查引用图；
  4. 直接刷新 /reports 返回 404 → 服务器没配 SPA history fallback，或改用 hash 路由；
  5. 构建因 initial 超限失败 → 首屏包超过 maximumError，把重型页面改为懒加载；
  6. OnPush 下数据变了但视图不动 → 原地修改数组/对象没产生新引用，用 set/update；
  7. 组件样式触发预算错误 → 单组件样式超 8kB，拆分或提全局。

自测 3 题（含答案） ​

  1. 路由懒加载和组件静态 import 的本质区别是什么？ —— 静态 import 把模块放进当前 chunk，启动时就要下载解析；loadComponent 中的动态 import() 把模块放到独立 chunk，只有路由匹配时才请求。前者影响首屏体积，后者把成本推迟到真正访问时。

  2. 为什么 @defer 里的组件有时没被拆出去？ —— 只有当依赖"仅"在该延迟块中使用时，Angular 才能把它移入延迟 chunk。如果同一组件在块外也被静态引用，打包器必须把它保留在主包。拆包前要检查引用图。

  3. OnPush 能减小包体积吗？ —— 不能。OnPush 影响的是运行时变更检测的范围与频率，不改变打包结果。减小体积靠懒加载、延迟加载和删除无用依赖；OnPush 与 signal 配合减少的是不必要的组件检查与计算。
