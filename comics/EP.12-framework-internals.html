EP.12 Angular 内部那点事 ​

对应正文：12-internals（1 注入器是一棵树 / 2 机制拆解 / 3 可运行示例 / 4 代码拆解 / 5 常见坑）· 配套示例：internals

剧情回顾 ​

  • 第 1 格：像素酱发现 Zone.js 猴子补丁把 setTimeout、fetch、XHR 全给包了一层，每个异步回调后都触发全局 change detection。这就是为什么一改 async 就变慢——隐式兜住一切，回调结束后全量扫描。
  • 第 2 格：码叔拆解 zoneless 下的三条刷新路径——① signal 写入标记依赖消费者为脏、② 模板事件把当前组件视图标记为脏、③ markForCheck() 从当前视图到根路径打脏标记。三条最终都汇合到同一套异步调度，而非全量扫描。
  • 第 3 格：标签君做实证对比——Zone.js 时代 setTimeout(plain++) 会刷新（patched），zoneless 下同一段代码不刷新（没通知）；但 fetch(...).then(reactive.update) 能刷新（signal 写入通知调度器）。
  • 第 4 格：码叔结案——注入器树与组件树平行，provider 覆盖只作用于子树；detectChanges() 同步局部，markForCheck() 异步向上。框架行为可以用最小实验验证。

知识点拆解 ​

第 1 格 · 注入器是一棵树 ​

Angular 的依赖注入不是一张全局表，而是一棵与组件树平行的注入器树：

ts
@Component({
  selector: 'app-greeting',
  // 组件级 providers 创建子注入器，覆盖祖先同名 Token
  providers: [{ provide: GREETING, useValue: '子注入器的值' }],
  template: '<p>注入结果：{{ greeting }}</p>',
})
export class Greeting {
  protected readonly greeting = inject(GREETING);
}

inject(GREETING) 从当前组件的元素注入器开始查找，逐级向上，最后才到环境注入器。因为 Greeting 自己声明了 provider，它在第一站就命中，根级值被遮蔽。覆盖只作用于这棵子树——兄弟组件继续读根级值，Greeting 内部嵌套的子组件继承组件级值。

第 2 格 · zoneless 的三条刷新路径 ​

一次 signal 写入经过这些步骤：

  1. 写入 signal，标记依赖它的消费者为脏；
  2. 调度器异步安排一次变更检测（不阻塞当前调用栈）；
  3. 从脏视图向上标记祖先，确保检查路径可达；
  4. 刷新过程中检查被标记的视图，更新 DOM。

模板事件绑定是另一条入口——点击按钮时，框架把该组件视图标记为脏并安排刷新。两条路径最终汇合到同一套调度。

第 3 格 · detectChanges vs markForCheck ​

手段作用范围时机
signal 写入依赖该 signal 的视图异步调度
模板事件绑定当前组件视图异步调度
markForCheck()当前视图到根路径下一次 tick
detectChanges()当前视图及子视图同步立即

detectChanges() 不管 OnPush 标记、不刷新祖先、不安排后续 tick，适合"必须马上同步 DOM"的场景（如测量元素尺寸前）。markForCheck() 不执行检查，只把路径标记为需要检查，等待下一次调度。

第 4 格 · OnPush 不是"不检查" ​

ts
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class CdLab {
  private readonly cdr = inject(ChangeDetectorRef);
  protected plain = 0;
  protected readonly reactive = signal(0);

  protected bumpPlainLater(): void {
    // 异步回调修改普通字段：OnPush 下不会自动刷新
    setTimeout(() => { this.plain++; }, 0);
  }

  protected bumpReactive(): void {
    this.reactive.update((v) => v + 1);
  }
}

普通字段没有任何机制知道它变了。setTimeout 回调执行完毕后，框架不会收到"需要检查"的通知。signal 不同——写入会通知所有读取过它的视图。OnPush 只是"只对通知响应"，而不是"不检查"。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. setTimeout 里改普通字段页面不动 → zoneless 下没有收到检查通知，改用 signal 或调 markForCheck()；
  2. 修改 signal 里的对象属性，视图不更新 → 引用未变，signal 认为值相同，返回新对象或用 update 替换引用；
  3. 事件回调里 inject() 报上下文错误 → 不在注入上下文，在字段初始化或构造函数中注入，或用 runInInjectionContext；
  4. 调了 detectChanges() 祖先模板仍旧没变 → 它只检查当前视图及子视图，需要向上通知时用 markForCheck()。

自测 3 题（含答案） ​

  1. 组件级 providers 会覆盖根级，为什么兄弟组件不受影响？——provider 注册在组件自己的元素注入器上，查找从当前节点向上进行。兄弟组件不在该子树里，查找路径不经过它的注入器，覆盖范围是子树而非全局。
  2. detectChanges 与 markForCheck 的本质区别是什么？——detectChanges() 同步执行检查，范围是当前视图及子视图，绕开 OnPush 的脏标记；markForCheck() 只打标记并让检查路径可达，实际检查由后续调度完成。
  3. 为什么 zoneless 下改普通字段不会刷新？——zoneless 不依赖 Zone.js 拦截异步任务，只响应明确通知：signal 写入、模板事件、markForCheck()、AsyncPipe 等。setTimeout 修改普通字段没有产生任何通知，调度器不知道需要检查。
