EP.13 导航链上的三道门 ​

对应正文：13-routing-advanced（1 导航判定链 / 3 Resolver / 4 canMatch + 懒加载 / 6 常见坑）· 配套示例：routing-form

剧情回顾 ​

  • 第 1 格：像素酱直接访问 /admin，组件创建完才开始查权限，懒加载 chunk 也已经下载。守卫放在组件里，等于先开门再查证件。
  • 第 2 格：码叔画出一次导航的五关——canMatch 结构匹配、canActivate 允许激活、ResolveFn 准备数据、创建组件、canDeactivate 离开确认。
  • 第 3 格：标签君用同一份 role = guest 对比：canMatch 让路由直接不匹配、chunk 不下载；canActivate 时 chunk 已下载，只能返回 UrlTree 去登录页。
  • 第 4 格：码叔结案——越早拦截，代价越小；canMatch 管路由是否存在，canActivate 管是否进门，Resolver 管激活前备料。

知识点拆解 ​

第 1 格 · 守卫的时机决定代价 ​

路由不是「点链接 → 换组件」，而是一条有顺序的判定链。把权限检查放进组件，框架必须先把组件与懒加载 chunk 准备好，才发现无权访问：

ts
// 文件：src/app/admin.ts（错误示范）
ngOnInit(): void {
  if (this.auth.role() !== 'admin') {
    this.router.navigate(['/']);
  }
}

这段代码能「拦住」页面，但拦截发生得太晚：chunk 已下载、组件已实例化、导航历史也可能多一条。

第 2 格 · 五关的顺序 ​

阶段守卫失败后果
匹配CanMatchFn该路由被跳过，继续尝试下一条
激活CanActivateFn阻止激活，可返回 UrlTree
解析ResolveFn导航不完成，用户看不到半成品
创建组件渲染视图并绑定输入
离开CanDeactivateFn停留在当前页面

函数式守卫用 inject() 取依赖，返回 true / false / UrlTree：

ts
export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  return auth.signedIn() || inject(Router).createUrlTree(['/login']);
};

false 只会取消当前导航，页面停在原地；UrlTree 会把用户带去登录页，并保留正确的导航历史。

第 3 格 · canMatch 与 canActivate 的差别 ​

canMatch 更早执行。身份不足时，这条路由根本不参与匹配，后面的兜底组件接手，懒加载 chunk 不会下载：

ts
{
  path: 'admin',
  canMatch: [adminMatch],
  loadComponent: () => import('./admin').then((m) => m.Admin),
}

Resolver 则在激活前把数据准备好，配合 withComponentInputBinding() 直接绑定到组件输入：

ts
readonly id = input.required<string>();
readonly profile = input.required<UserProfile>();

第 4 格 · 选阶段的判断标准 ​

  • 决定「这条路由是否存在」→ canMatch；
  • 决定「用户能否进入」→ canActivate；
  • 决定「进入前数据是否就绪」→ Resolver；
  • 决定「能否离开未保存页面」→ canDeactivate。

把「是否存在」放进 canActivate，是 chunk 白下载的典型原因；把轮询或用户交互后的数据塞进 Resolver，则会让首屏一直等。

坑点清单 ​

🔗 正文对照：常见坑表格

  1. 用 canActivate 管路由是否存在 → 权限不足仍会下载 chunk，改用 canMatch；
  2. 守卫返回 false 却期待跳转 → 页面停在原地，返回 UrlTree 才会导航；
  3. Resolver 里塞轮询或交互数据 → 阻塞整次导航，只放首屏必需的数据；
  4. 在组件构造函数里读 ActivatedRoute 快照 → 参数在导航过程中可能变化，用输入绑定或流。

自测 3 题（含答案） ​

  1. canMatch 与 canActivate 最本质的区别是什么？——canMatch 在结构匹配阶段执行，不匹配时该路由被跳过、懒加载 chunk 不下载；canActivate 在激活阶段执行，此时 chunk 与组件准备已经发生，只能阻止或重定向。
  2. 为什么返回 UrlTree 比返回 false 更好？——false 只取消当前导航，用户停留在原页面；UrlTree 会发起一次新的目标导航，并保留正确的历史，适合登录重定向。
  3. Resolver 适合承载哪类数据？——首屏渲染必需、失败时不应进入页面的数据，例如详情页实体与权限上下文；轮询、局部刷新与用户交互后加载的数据应留在组件或服务里。
